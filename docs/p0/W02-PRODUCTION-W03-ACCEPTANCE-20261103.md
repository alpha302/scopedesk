### 先失败，再修复

新增 `TestW03HashDoesNotBlockExistingSession`：一个登录停在真实密码哈希入口，已有会话访问 `/api/me`。旧实现因全局 mutex 被持有超过 500ms，明确失败：`W03: password hashing holds the global mutex and blocks an existing session API`。该测试是确定性的同步复现；另有不插入停顿的真实哈希测量，不以 8 路并发登录为目标。

[失败运行 41563403205](https://github.com/alpha302/scopedesk/actions/runs/41563403205)：鉴权结果 6 PASS、1 FAIL、0 SKIP；失败正是上述复现。真实哈希三轮测量另行通过。原始证据：`evidence/w03-red-41563403205/`。

### 文件和行为

- `main.go`：移出 login 实现，增加私有哈希依赖和有界排队状态；用户失效时递增认证版本，识别哈希期间发生的密码/角色/停用变化及停用后重新启用。
- 新增 `login.go`：密码哈希移到全局锁外。每进程最多 **1 个哈希计算 + 2 个等待请求**，不提高原每 IP 8 次失败限制；在途请求预留名额，防止解锁后并发绕过限制。排队满对已知/未知账号统一返回 503，取消返回 408；计算后重新校验账户状态及版本，再创建会话。哈希算法仍为原 PBKDF2 SHA256 600000 次；Cookie、CSRF、会话期限和原 API 字段含义保持。
- 新增 `w03_login_test.go`：全局锁阻塞、哈希期间账户变化（4 子例）、第 8 次限制预留、队列上限/取消/恢复、正在计算时取消不签发会话、未知/停用/错误密码统一错误，以及 3 轮真实哈希测量。

### 已知风险与未完成项

W03 当前只改变登录路径；用户管理/密码修改中的原有哈希锁行为未改。本次不实现账户级/共享登录限流 W37，也不实现会话持久化 W38；状态和限流仍是单实例内存状态，重启仍导致会话失效。排队上限是保守保护参数，503/408 是新的运行结果，客户端可能需要重试；不是高并发容量承诺。取消不能中止已经开始的 PBKDF2，但会阻止签发该请求的会话。
