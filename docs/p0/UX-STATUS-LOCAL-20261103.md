## 已实现行为

1. HTTP 配置与实测分离。概览汇总可见目标的 HTTP 许可配置，明确仅证据模式不发送平台 DNS/HTTP 请求；目标卡片解释任务模式和项目策略；资产说明历史记录与“尚无 HTTP 实测”，不把许可当作已经探测，不把未知旧负面状态猜成 HTTP 失败。旧任务未记录模式时明确显示无法推断。
2. 完成作业的结果按来源和实际处理标志显示成功、部分成功、失败或结果待核对。旧 `jobs.status`/数据库枚举不改；不拿 `absence_usable=false` 或仅证据模式的 `stats.complete=false` 推定来源失败。只有记录到留存结果才使用“已有结果已保留”字样，缺少历史完成证据保持待核对。
3. 无变化的正常运行默认折叠；新增/下线/恢复/IP 变化和当前异常默认展开。相同目标连续相同问题标次数，较早的重复问题折叠；跨目标不会串数，出现新变化仍展开。仍保留每条运行和其原始编号。修正来源统计表的缺失表头，避免字段过滤/新增/尝试/错误错列；已结束的旧作业缺节点信息不再显示“待领取”。
4. 事件以中文摘要为主，原始 JSON 收进“查看原始证据”。无独立 HTTP 依据的旧异常/恢复事件明确标历史变化，不把原来的混合状态追认为真实 HTTP 下线。不删除历史，不改变事件生成、去重或阈值。
5. `/api/state` 仅新增 `source_capabilities`，从现有清单提供来源名称、启用情况、支持粒度和仅证据模式能力，不提供命令、参数、路径或凭据。保留原 `source_options`。前端对 exact + subfinder、外部插件 + 仅证据及自定义清单限制置灰并解释；不通过扩大目标范围解决不兼容。
6. 手动入队、启用计划及调度入队前共用来源配置检查。旧不兼容计划保留配置并记录 `schedule_error`/重试时间，不继续创建相同失败作业；不自动删除、禁用或改写已有计划。前端移除的是当前表单的不兼容项，会提示保存计划才修改已存配置；关闭旧计划时保留其原来源，避免因表单已清空而无法关闭。

`ScopeGuard`、项目/范围限速、请求预算、租约、外部主动插件禁用、逐请求授权检查均保留；没有提高限速、增加 worker 或扩大扫描范围。无迁移，无原 API 字段含义修改。

- 实际生产共用的纯 Go 来源政策函数，在 Windows 直接执行 8 组组合用例，全部通过（JSONL 包含父测试，共 9 个 PASS 结果）。命令只编译 `source_policy.go` 与其测试，不受项目 Linux 专用实现影响。
