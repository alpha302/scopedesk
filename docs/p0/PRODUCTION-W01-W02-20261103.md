地址分类共 12 个样例：8 个普通公网/私网/回环/保留地址的预期通过；以下 4 个应拒绝的嵌入地址仍被接受：

- `64:ff9b::7f00:1`：NAT64 形式，嵌入 127.0.0.1。
- `64:ff9b::a00:1`：NAT64 形式，嵌入 10.0.0.1。
- `2002:7f00:1::1`：6to4 形式，嵌入 127.0.0.1。
- `2002:a00:1::1`：6to4 形式，嵌入 10.0.0.1。

实际拨号另有 4 个受控样例。容器使用 `--network none`，没有外网接口/默认出口；这 4 个 IPv6 地址只绑定在容器 loopback，每次拨号前先确认地址归该回环接口所有。受控 DNS 仅返回当前样例地址，运行产品原有 HTTP DialContext、LocalRateLimiter（平台/范围仍为 5 RPS）与预算。测试端口为容器自身 IPv6 的 80，无真实外部目标。

**4 个样例均得到 HTTP 200，各记录 2 次 HTTP 请求（首页和 favicon）。** 每个样例随后新增测试黑名单项，再执行同一主机画像，HTTP 请求数均未增加；说明这个受控路径的黑名单仍可阻止后续请求。每个样例累计观察到 27 次 ScopeGuard 调用。

这证明当前分类器会放行并实际拨号到上述 IPv6 地址。**实验没有运行真实 NAT64/6to4 转换器，因此不证明某个生产路由可转发至嵌入的私网 IPv4，也不是已验证的生产内网利用链。** 合法转换地址、更具体前缀例外、重绑定、重定向与双栈回退仍需在 W02 修复时分别验收。
